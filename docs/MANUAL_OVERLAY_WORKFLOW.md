# Manual overlay and tracking — implementation status

Branch: `refactor/manual-overlay-workflow`. Updated 2026-09-21. **The face-specific changes are NOT built or tested at the user's request.** Source inspection and successful GitHub commits are not evidence of compilation, GUI behavior, tracking quality, crash recovery or encoded-video fidelity. This branch has not been merged into `main`.

## Required behavior and user journey

The goal is **not** to create a separate storage system for its own sake: the user must be able to identify a face missed by Auto, draw a mask for that particular face, track it across moving video, correct it without affecting other faces, and see every verified mask in preview and final video. Each manually identified missed face has a stable GUID and independent explicit-alpha corrections, validated motion samples and failure boundaries. A correction to A must not erase B. Never hold an earlier face mask over a missing tracking sample. Preview and export should combine current Auto, separate legacy/global manual pixels and verified target-specific coverage. Corrupt target state and unresolved nonempty face gaps should block rather than silently export unblurred faces. An all-zero explicit correction terminates **only its own face**; no legacy/global mask is assigned an inferred face ID.

**Concrete steps, missing features, and unexecuted acceptance scenarios:** [`MANUAL_FACE_WORKFLOW_ACCEPTANCE.md`](MANUAL_FACE_WORKFLOW_ACCEPTANCE.md). Storage collision work supports the workflow but does not establish correct moving-face tracking or final output.

## Persistence and lifecycle corrections — 2026-09-21

### Core editor ownership and lifecycle

- **Root issue:** `FramePreviewViewModel.PersistCurrentMask()` previously wrote the selected face's alpha into the legacy/global `FrameMaskProvider`. It now routes a selected face through `CommitSelectedManualTargetEdit()` first. Direct frame-load/replacement and session initialization attempt saving before replacing the bitmap; same-frame reload preserves dirty alpha and Undo, and disposal attempts a final save. [Core routing `47cb3a9`](https://github.com/doanythingK/FaceShield_/commit/47cb3a9ea5b1a367566aa3b0a346e42c480357e8).
- **Other error paths:** Save-button and Go Back errors are shown instead of escaping the async handler or navigating away with dirty face pixels. An incidental full-file rewrite typo (`FlickerIssues`) was immediately reverted to the existing `FlickerFrames` member. Ordinary window close attempts to save and cancels closing if the save fails. [Save/Back `0648b10`](https://github.com/doanythingK/FaceShield_/commit/0648b10987e4700c0df751da974f883bf15cb2de), [typo correction `2934434`](https://github.com/doanythingK/FaceShield_/commit/2934434d79a8bd8b4fc2645475e1fb93741269e0), [window close `fc20a8e`](https://github.com/doanythingK/FaceShield_/commit/fc20a8e4ae447f3fb5fa3a8e78ee3c5b90b7758e).

### Competing edits and direct writer integration

- **Initial conflict protection:** `CommitIfUnchangedForVideo` compares target IDs, alpha keyframes, tracking samples and failure metadata with the disk document under a persistent sidecar lock file. Correction, tracking and detached new-face creation use expected-state comparison. [Compare-and-commit `9d5d88a`](https://github.com/doanythingK/FaceShield_/commit/9d5d88a0cf40d722850c948ab2eab8f23b8f7a9a), [correction `df8065f`](https://github.com/doanythingK/FaceShield_/commit/df8065f32dcc5624ed88ca724ee7acffb3fd5c05), [tracking `b843ea6`](https://github.com/doanythingK/FaceShield_/commit/b843ea68521718964397798f521c6c8e034e7de8), [creation `8a90b7c`](https://github.com/doanythingK/FaceShield_/commit/8a90b7c62b7bbcb5a46bb4bc303cb57922e4d63e).
- **Direct `ManualOverlayTargetWorkspace.Save()` no longer overwrites unconditionally:** A workspace stores its last loaded/confirmed persisted snapshot, compares it to disk when directly saving, and advances its baseline only after successful persistence. Disk-first correction/tracking committers now record their newly saved snapshot after live publication, so later direct saves do not falsely conflict with their own changes. [Workspace `575e2b2`](https://github.com/doanythingK/FaceShield_/commit/575e2b2941e642f3bb4de62fd7cde943f0cecf34), [correction baseline `641c133`](https://github.com/doanythingK/FaceShield_/commit/641c1337827503a1ec6ab6faf3d1514abf972f45), [tracking baseline `4e824f5`](https://github.com/doanythingK/FaceShield_/commit/4e824f59803e69d22b20d8daa88f58dac35ed31c).
- **Idempotence and legacy API change:** If the disk document already equals the requested new state, comparison returns successfully without writing it again; this also supports a detached new-face instance whose initial baseline precedes its successful disk-first creation. `SaveForVideo` now allows only seeding an empty document or an identical repeat. Updating existing state through that API requires migrating the caller to `CommitIfUnchangedForVideo(expected,updated)`; an older caller relying on unconditional replacement will now receive a conflict. Optional `stateDirectory` remains supported for synthetic scripts. [Idempotence `3a2702a`](https://github.com/doanythingK/FaceShield_/commit/3a2702ad44f4c24d2b765355d9fedeeceece292b), [seed-only API `c1513e9`](https://github.com/doanythingK/FaceShield_/commit/c1513e948453623750d28f2b861b84a6c074f4c4).

## Known limitations / still unfinished

1. **The core purpose is not proven:** An actual missed face's moving mask must be checked end-to-end from manual draw through tracking, separate-face correction, preview and encoded video. No such execution has been performed. Face list ordinal labels can change after reopening despite stable GUIDs; friendly names/thumbnails are not persisted.
2. **Uncooperative writers and conflict recovery:** A separate process bypassing `CommitIfUnchangedForVideo`/the sidecar lock (or calling the lower-level `ManualOverlayStateStore.Save` directly) can still race. Conflicts fail closed and currently require reload/manual reconciliation; there is no automatic three-way merge. Source evidence is video length and modification time, not a content hash.
3. **Shutdown and navigation edge cases:** Forced process/OS termination or permanent disk write failure cannot guarantee recovery of memory-only edited pixels. Ordinary close can be cancelled but may not cover every OS shutdown path. A direct programmatic timeline setter can leave selection visually inconsistent when an asynchronous preview save rejects; confirm exception/cancellation and ownership transitions in real GUI.
4. **Other export entry points:** `WorkspaceExportCoordinator` wraps target state; unrelated direct `VideoExportService`/other export consumers may bypass its pre-save guard or target mask adapter. Audit all production call sites before claiming universal face-specific export protection.
5. **Runtime, accuracy and memory:** Full-frame per-face composition, repeated fingerprints, seek/decoder failures, zero-sample retrack exceptions, large/VFR video and packaged FFmpeg behavior remain unmeasured. Actual decoded preview vs encoded video parity has not been established.
6. **Verification deliberately deferred:** Compilation, regression scripts, injected disk failure, concurrent writer test, real multi-face GUI, preview/encoded-output comparison and Windows/macOS builds/packaging were **not executed for the new face-specific implementation**. [Quality Gate #299](https://github.com/doanythingK/FaceShield_/actions/runs/35489593929) pertains only to old [`554081b`](https://github.com/doanythingK/FaceShield_/commit/554081b7c95c279dee22b5d51f3ad4d447c8d615), not these changes.

Subsequent changes must be committed on this branch and recorded here with reason, commit link, actual verification or explicit deferral, and remaining limitations. Do not equate source intent with tested behavior.
