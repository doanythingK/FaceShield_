# Manual overlay and tracking — implementation status

Working branch: `refactor/manual-overlay-workflow`. **All changes dated 2026-09-21 remain unbuilt and untested at the user's request.** A source commit is not evidence of successful compilation, GUI operation, actual multi-face tracking, data preservation under injected failures, or encoded-video correctness. No merge to `main` was requested.

## Required behavior

Each manually marked missed face has a stable GUID, independent alpha/keyframes/validated motion samples and failure boundaries. Correcting face A must not remove face B. Never hold an old mask over a missing motion sample. Preview/export must combine current-frame Auto, separate legacy manual pixels and all confirmed face-specific pixels. Invalid persisted targets, uncorrected failure boundaries and unresolved nonempty-source gaps must not silently produce successful unblurred output. Do not infer face IDs from legacy/global masks.

## Older verified baseline — not verification of this branch's new code

`FrameMaskProvider` separates Auto and legacy/manual pixels; `ManualMaskEditorLayer` preserves strokes overlapping Auto; `ManualPreviewCompositeCache` caches the older global preview. `ManualMaskTrackingService` validates feature motion and failure boundaries, and the legacy `ManualMaskTrackStore` v3 requires contiguous samples. [Quality Gate #299](https://github.com/doanythingK/FaceShield_/actions/runs/35489593929) passed configured Windows/macOS builds and synthetic checks for older commit [`554081b`](https://github.com/doanythingK/FaceShield_/commit/554081b7c95c279dee22b5d51f3ad4d447c8d615) **only**.

## Central persistence and creation follow-up (2026-09-21, unverified)

### Remove a duplicate partial member

- **Problem:** Both `FramePreviewViewModel.ManualTargetLifecycle.cs` and `.ManualTargetUi.cs` declared `ManualTargetEditableFrameIndex`, which is a duplicate C# member. The UI implementation also checks that a selected target and actual editable bitmaps exist.
- **Change:** Delete only the duplicate lifecycle declaration and retain the guarded UI implementation. [`7a92e0a`](https://github.com/doanythingK/FaceShield_/commit/7a92e0a55952cf1cfe42e3909ca02e8652ab1619).
- **Verification:** Static source comparison only, not compilation.

### Route the core writer to the selected face

- **Problem:** A direct `PersistCurrentMask()` wrote a selected face's editable pixels to the legacy global `FrameMaskProvider`, even after separate GUI guards had been added. Direct frame replacement, same-frame reload and disposal could also discard pixels/Undo.
- **Change:** `FramePreviewViewModel.PersistCurrentMask()` now calls `CommitSelectedManualTargetEdit()` before any legacy-provider path when a target is selected. Session initialization, direct timeline/manual frame loading, exact and playback frame replacement attempt to persist/retain Undo before replacing the current editor; failure prevents replacement in the guarded paths. Same-frame editability no longer resets dirty pixels or clears Undo. The disposal path makes a best-effort final commit. [`47cb3a9`](https://github.com/doanythingK/FaceShield_/commit/47cb3a9ea5b1a367566aa3b0a346e42c480357e8).
- **Limit:** A shutdown after a disk-full/unwritable-state failure cannot guarantee recovery of memory-only pixels; `Dispose()` logs/reports the failure but cannot force the application to stay open. Frame transitions not mediated by the frame-list coordinator can leave the timeline selection visually out of sync after a save rejection. The newly modified asynchronous paths still need exception, cancellation and UI-thread tests.

### Include creation in disk conflict checks

- **Problem:** Detached `CreateManualTarget()` formerly called `staged.Save()` without checking whether another correction/track had changed on disk since its load.
- **Change:** Capture the detached workspace's exact pre-create snapshot, add the new face only to the staged instance, then call `CommitIfUnchangedForVideo(videoPath, expected, staged.Snapshot())` before swapping the live face list. [`8a90b7c`](https://github.com/doanythingK/FaceShield_/commit/8a90b7c62b7bbcb5a46bb4bc303cb57922e4d63e).
- **Limit:** Other direct `ManualOverlayTargetWorkspace.Save()`/`ManualOverlayWorkspaceStore.SaveForVideo()` callers still bypass this compare-and-commit API; the new-face command outside the GUI error handler can still surface its exception. A detected conflict requires reload/merge by the user; it is not resolved automatically.

### Handle direct Save/back errors

- **Problem:** `WorkspaceViewModel.OnSaveRequested` is `async void` and could throw on a target persistence failure before entering its nested export catch; `GoBack` could throw on the same failure instead of reporting it and retaining the current view.
- **Change:** Save catches target commit/export errors and does not trigger an extra preview-mask save from its workspace-state `finally` after an initial mask failure; the back command reports failed commit/queued save and returns before `_onBack`. [`0648b10`](https://github.com/doanythingK/FaceShield_/commit/0648b10987e4700c0df751da974f883bf15cb2de). An accidental `FlickerIssues` member-name typo from that full-file update was immediately corrected back to the original `FlickerFrames`. [`2934434`](https://github.com/doanythingK/FaceShield_/commit/2934434d79a8bd8b4fc2645475e1fb93741269e0).
- **Verification:** Reviewed GitHub commit patches; no compilation, injected save failure, UI, playback, export or CI was run.

## Remaining implementation and verification

1. **Shutdown and navigation edge cases:** A permanent disk write failure during application shutdown still loses any memory-only edited pixels; blocking app-close needs an application-lifetime UI contract. Review whether direct programmatic timeline setters should revert their selection when `OnFrameIndexChanged` rejects a save, and keep new-frame decoding/fallback errors distinct from save failures. Avoid silently swallowing genuinely failed workspace-state persistence.
2. **Uncooperative writers and recovery:** `ManualOverlayTargetWorkspace.Save()`/`ManualOverlayWorkspaceStore.SaveForVideo()` remain direct unguarded APIs. An external process ignoring the sidecar lock can still race the new compare-and-commit writers. Conflicts currently require an explicit reload rather than an automated three-way merge.
3. **Runtime and performance unknown:** Full-frame per-face composition, repeated source fingerprints, video seeking, large videos and packaged FFmpeg resources have unmeasured memory/latency and correctness. A decoder exception before a zero-sample retry returns still reports failure instead of showing existing verified coverage.
4. **Deferred validation:** Only when the user resumes checks: compile; synthetic A/B face edits, zero-sample retries, injected disk write failure and competing writer tests; frame/Undo/disposal failure tests; real multi-face GUI; decoded-preview versus encoded-output pixel comparison; Windows/macOS builds/packages. **No compilation, tests, CI, GUI or actual encoded export were run for these 2026-09-21 changes.**

**Change-log rule:** Record every further commit, motivation, changed files, actual verification/deferred verification and unresolved risks on this same branch. Source intent must never be described as tested behavior.
