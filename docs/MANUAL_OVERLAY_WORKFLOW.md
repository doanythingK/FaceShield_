# Manual overlay and tracking — implementation status

Working branch: `refactor/manual-overlay-workflow`. **All 2026-09-21 changes remain unbuilt and untested at the user's request.** Committed code is not proof of compilation, GUI behavior, accurate tracking, data preservation or encoded video correctness. This branch has not been merged into `main`.

## Required behavior

Each manually marked missed face has a stable GUID, independent alpha/keyframes/validated motion samples and failure boundaries. Correcting face A must not remove face B. Never hold an old mask over a missing motion sample. Preview/export must combine current Auto, separate legacy manual pixels and all confirmed face-specific pixels. Invalid persisted targets, uncorrected failure boundaries and unresolved nonempty-source gaps must not silently produce successful unblurred output. Do not infer face IDs from legacy/global masks.

## Older verified baseline — not verification of this branch's new code

`FrameMaskProvider` separates Auto and legacy/manual pixels; `ManualMaskEditorLayer` preserves strokes overlapping Auto; `ManualPreviewCompositeCache` caches the older global preview. `ManualMaskTrackingService` validates feature motion and failure boundaries, and the legacy `ManualMaskTrackStore` v3 requires contiguous samples. [Quality Gate #299](https://github.com/doanythingK/FaceShield_/actions/runs/35489593929) passed configured Windows/macOS builds and synthetic checks for older commit [`554081b`](https://github.com/doanythingK/FaceShield_/commit/554081b7c95c279dee22b5d51f3ad4d447c8d615) **only**.

## Further stabilization — disk conflict, export and playback (2026-09-21, UNVERIFIED)

### Detect competing saved state before replacing the target document

- **Problem:** `lock(workspace)` alone cannot protect two independent workspace instances or a second process; the last save can silently replace another face's correction or track.
- **Change:** `ManualOverlayWorkspaceStore.CommitIfUnchangedForVideo` normalizes and compares all target IDs, alpha keyframes, track samples and failure metadata against the current disk state while holding a persistent sidecar lock file (`FileShare.None`). It rejects a mismatch before writing; both the correction and tracking committers use this entry point. [`9d5d88a`](https://github.com/doanythingK/FaceShield_/commit/9d5d88a0cf40d722850c948ab2eab8f23b8f7a9a), [`df8065f`](https://github.com/doanythingK/FaceShield_/commit/df8065f32dcc5624ed88ca724ee7acffb3fd5c05), [`b843ea6`](https://github.com/doanythingK/FaceShield_/commit/b843ea68521718964397798f521c6c8e034e7de8).
- **Limit:** Only writers participating in this commit API obey its lock. The existing direct `SaveForVideo`/`ManualOverlayTargetWorkspace.Save` and detached new-face creation still bypass it; source evidence is video length/mtime, not a content hash. Cross-process and disk-conflict behavior was not exercised.

### Guard direct export and pre-view session initialization

- **Problem:** `WorkspaceExportCoordinator.ExportAsync` can be called outside a toolbar Save; GUI-only guard installation leaves viewless/manual initialization paths open.
- **Change:** `ExportAsync` now checks `ToolPanel.ManualTargetExportGuard` on the UI thread before entering the export core and loading masks, rejecting a failed correction commit. `FramePreviewViewModel.ManualTargetLifecycle` exposes guard installation, called by `WorkspaceSessionPlaybackCoordinator` constructor for manual workspaces. The coordinator checks face-save before adopting a new session and before stopped-frame refresh, attempting to preserve and restore Undo when the same frame is refreshed. [`61d4a32`](https://github.com/doanythingK/FaceShield_/commit/61d4a32fe2b4bba78137038d7b41668a3b2b2881), [`676e831`](https://github.com/doanythingK/FaceShield_/commit/676e831b616854a4759f9d43ea81c674691aeaa8), [`47081ee`](https://github.com/doanythingK/FaceShield_/commit/47081ee4f37fbabb305831a833fccbe6256d6d27).
- **Limit:** Direct `FramePreviewViewModel` calls can bypass the coordinator, and direct `VideoExportService` callers bypass `WorkspaceExportCoordinator`. No run proved export is blocked on failure.

### Distinguish playback-cleared Undo from user-exhausted Undo

- **Problem:** `FrameList.NotifyPlaybackStopped` invokes its state-changed handler before its stopped handler. The former clears the shared `_maskUndo` stack; archiving the empty stack afterward previously erased the last saved per-face Undo archive.
- **Change:** `PreserveManualTargetUndo` now retains a prior archived stack when the shared stack is incidentally empty. An explicit Undo completion requests `clearWhenEmpty: true` so a genuine user-exhausted stack is removed. [`6cd171d`](https://github.com/doanythingK/FaceShield_/commit/6cd171d06f368c87dee7c8e90d30918d7521cf40), [`5b66b38`](https://github.com/doanythingK/FaceShield_/commit/5b66b384e3d5cecaefc7567628ce06f869c1cbdd).
- **Limit:** The archive remains session-only. Direct same-frame editing and frame-replacement paths still require integration/verification.

## Remaining implementation and verification

1. **Central edit ownership — critical:** `FramePreviewViewModel.PersistCurrentMask()` is STILL a legacy/global writer; it does not route a selected face into target-owned persistence. Direct `OnFrameIndexChanged` / `LoadManualFrameAsync`, `EnsureCurrentManualFrameEditable`, `InitializeSession`, frame replacement and `Dispose` can clear or misroute pending selected-face pixels. The surrounding guards do not establish complete prevention. Do not claim this fixed until the core method and disposal paths change.
2. **Competing writers:** Move detached new-face creation and all `ManualOverlayTargetWorkspace.Save` / direct `SaveForVideo` paths onto the same conflict-aware commit contract; design recovery or explicit reload/merge on conflicts. Confirm export consumers outside the workspace coordinator cannot silently omit face-owned state.
3. **Runtime and performance unknown:** Full-frame per-face composition, repeated source fingerprints, video seeking, large videos and packaged FFmpeg resources have unmeasured memory/latency and correctness.
4. **Deferred validation:** Only when validation resumes: compile; synthetic A/B face edits, zero-sample retries, injected disk write failure and competing writer tests; frame/Undo/disposal failure tests; real multi-face GUI; decoded-preview versus encoded-output pixel comparison; Windows/macOS builds/packages. **No compilation, tests, CI, GUI or actual encoded export were run for these 2026-09-21 changes.**

**Change-log rule:** Record every further commit, motivation, changed files, actual verification/deferred verification and unresolved risks on this same branch. Source intent must never be described as tested behavior.
