# Manual overlay and tracking — implementation status

Working branch: `refactor/manual-overlay-workflow`. **All changes dated 2026-09-21 remain unbuilt and untested at the user's request.** A committed source connection is not evidence of a successful GUI run, accurate face tracking, complete data preservation, or correct encoded output. This branch has not been merged into `main`.

## Required workflow and invariants

A manually marked missed face is tracked independently of Auto detections and other manual faces. Each face owns a stable GUID, editable alpha, correction keyframes, validated motion samples, and failure boundaries. Correcting face A cannot remove face B's track. An absent motion sample must not reuse a stationary earlier mask. Preview and export combine current-frame Auto, retained legacy manual coverage, and all confirmed face-specific coverage. Invalid persisted target data and unresolved target gaps must not produce an apparently successful unblurred export.

## Baseline verified before 2026-09-21 only

- `FrameMaskProvider` separates Auto rectangles and legacy manual pixels; `ManualMaskEditorLayer` preserves manual strokes overlapping Auto detections. `ManualPreviewCompositeCache` caches the legacy Auto/manual preview and dirty regions.
- `ManualMaskTrackingService` validates feature motion and stops on unreliable movement, scene cuts or decoder failures. The legacy global `ManualMaskTrackStore` v3 enforces contiguous samples and retains the longer valid same-source retry.

## Change log — 2026-09-21: further lifecycle, retry and safety changes (unverified)

### Retry status reflects retained coverage

- **Why:** A rejected shorter or failing retrack could be reported using the *attempted* segment even though the workspace retained a longer previous segment.
- **What:** `ManualOverlayTargetTrackingService.TrackForward` retrieves the actual retained, fingerprint-matching segment after `SetTrackSegment` and returns that saved segment and its frame count. It rejects an explicitly all-zero tracking source. [`33fd5ae`](https://github.com/doanythingK/FaceShield_/commit/33fd5aee00450053f7f1132abac942bca38eecf8).
- **Verification:** Deferred; no build, tracking invocation or source video run.

### Optional selection data cannot abort workspace open

- **Why:** `ManualOverlayTargetSelectionStore.Load` resolved the video-derived metadata path **outside** its error handler; a missing/invalid path could abort otherwise valid target-state opening.
- **What:** Path resolution is now inside the optional metadata error boundary, and temporary selection-file cleanup does not mask the original save exception. It still rejects source-evidence mismatches and unknown selection IDs. [`a426524`](https://github.com/doanythingK/FaceShield_/commit/a426524eeefa65c270d59b45cdbb3258fcc807b3).
- **Verification:** Deferred; no invalid-path test or GUI restart was run.

### Toolbar save, programmatic timeline selection and playback startup

- **Why:** `FramePreviewViewModel.PersistCurrentMask()` can write a dirty selected-target bitmap into the **legacy global manual layer** if invoked before target-owned persistence. UI-only pointer/keyboard hooks did not cover programmatic `FrameList.SelectedFrameIndex` updates or playback start. A target save failure could then clear the editor without saving its face-owned alpha.
- **What:** `WorkspaceView.axaml.cs` configured the existing synchronous `ToolPanel.ManualTargetExportGuard` to commit target-owned edits before the toolbar Save command invokes `WorkspaceViewModel.OnSaveRequested`. It archives Undo at pointer entry. [`0fc996f`](https://github.com/doanythingK/FaceShield_/commit/0fc996f65257b7e4cb14286654b2dfd162064c35).
- **What (timeline owner):** `WorkspaceSessionPlaybackCoordinator` commits pending selected-target edits and archives Undo before UI/programmatic `FrameList` selection changes and playback. On target-save failure, it blocks navigation, attempts to restore the selected frame and reports the failure; a rejected play request does not clear the dirty bitmap/Undo. [`88521b3`](https://github.com/doanythingK/FaceShield_/commit/88521b335673c474b7ff138948eec08963d2d940), [`78c0b77`](https://github.com/doanythingK/FaceShield_/commit/78c0b774237170eab9e1939b2f1ecb03319ce69d).
- **What (source consistency):** `FramePreviewViewModel.ManualTargetUi.cs` exposes `ManualTargetEditableFrameIndex`; removed its outdated `CanExportLegacyMask` blocker now that the export adapter is connected. [`9d56796`](https://github.com/doanythingK/FaceShield_/commit/9d56796592cd6058f711902eb9e4cb99af8757d9).
- **Verification:** Deferred; no compilation, GUI interaction, Actions or rendered output.
- **Remaining:** `PersistCurrentMask()` itself still uses the legacy writer; direct preview calls, disposal, asynchronous startup and alternative export entry points are not all covered.

### Finish target tracking persistence after an in-memory commit

- **Why:** Cancellation between `ManualOverlayTargetWorkspace.SetTrackSegment()` and `Save()` could leave preview using samples that export would not reload from disk.
- **What:** `ManualOverlayTargetTrackingService` accepts cancellation up to the commit boundary, but does not throw for cancellation between mutation and file save. [`3925d48`](https://github.com/doanythingK/FaceShield_/commit/3925d483333cb22cc77e42350eecfc82bc7720f4).
- **Verification:** Deferred; cancellation timing and file-write failure have not been exercised.
- **Remaining:** An actual `Save()` exception can still leave updated samples only in the live workspace; a transactional staged commit is not implemented. A late cancellation after a successful write may still produce a misleading cancelled UI status.

### Reject failed target writes on Save and Auto; restore target editor after Auto

- **Why:** A view-attached Save/Auto command could proceed to global persistence when face-specific persistence failed. The ordinary Auto completion handler rebuilds the legacy mask and clears a face's Undo stack. Clearing the view's Save guard at detachment also allowed later programmatic Save commands on a live workspace to bypass it.
- **What:** `FramePreviewViewModel.ManualTargetLifecycle.cs` adds `TryCommitPendingManualTargetEdit()`, which retains dirty pixels and exposes an error in the manual-tracking status if saving throws ([`25bcd68`](https://github.com/doanythingK/FaceShield_/commit/25bcd681e9783f05ae262066cc37d0a327cd4307)). `WorkspaceView.axaml.cs` uses it to block the view's Save, picker, new-face, pointer and keyboard paths on failure and leaves the Save guard connected while the workspace remains alive ([`c09564a`](https://github.com/doanythingK/FaceShield_/commit/c09564acbad634a7292c31071c3ce80ddad63f05)). `ManualTargetLifecycle` archives the selected face's Undo at Auto start, then restores its editable mask and archived Undo after the existing global Auto completion handler ([`3aa2bde`](https://github.com/doanythingK/FaceShield_/commit/3aa2bde3e32c56313686d75e0799947bad60e695)). `ToolPanelViewModel.SetAuto` invokes the same synchronous guard before programmatic and GUI Auto commands ([`79119e9`](https://github.com/doanythingK/FaceShield_/commit/79119e9d055fd01da985c25b07a116454068842f)).
- **Verification:** **Deferred by user request.** No build, automated checks, Actions status, manual GUI or actual encoded-output run on these changes.
- **Remaining:** `FramePreviewViewModel.PersistCurrentMask()` is not itself target-aware. View-independent direct calls to Save/Export/Auto that do not traverse a guarded command remain possible. Auto refresh and Undo restoration have not been observed in a real GUI. The mask still needs explicit preservation on direct view-model disposal.
