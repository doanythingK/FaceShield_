# Manual overlay and tracking — implementation status

Working branch: `refactor/manual-overlay-workflow`. **All 2026-09-21 changes are unbuilt and untested at the user's request.** Source commits do not establish successful GUI operation, accurate face tracking, complete data preservation, or correct encoded output. No merge to `main` was requested.

## Required workflow and invariants

A manually marked missed face is tracked independently of Auto detections and other manual faces. Each face owns a stable GUID, editable alpha, correction keyframes, validated motion samples and failure boundaries. Correcting A cannot remove B's track. Missing motion samples must never reuse a stationary earlier mask. Preview and export combine current-frame Auto, retained legacy manual coverage and all confirmed face-specific coverage. Invalid saved state or unresolved target gaps must not silently export an unblurred face.

## Baseline verified before 2026-09-21 only

- `FrameMaskProvider` separates Auto rectangles and legacy manual pixels; `ManualMaskEditorLayer` preserves strokes overlapping Auto. `ManualPreviewCompositeCache` caches the older global Auto/manual preview.
- `ManualMaskTrackingService` verifies feature motion and stops on unreliable motion, scene cuts or decoding failure. Legacy `ManualMaskTrackStore` v3 requires contiguous samples and retains a longer valid same-source retry.

## Change log — 2026-09-21 (no new build, CI, GUI or export validation)

### Retained retry status and optional selection loading

- **Why:** A rejected shorter retry could display its attempted frames instead of retained coverage; malformed optional selection metadata could abort opening a valid workspace.
- **What:** Return a retained, fingerprint-matching segment and its frame count, and refuse an all-zero explicit tracking source ([`33fd5ae`](https://github.com/doanythingK/FaceShield_/commit/33fd5aee00450053f7f1132abac942bca38eecf8)). Resolve selection metadata paths inside the error boundary and prevent temporary-file cleanup errors masking original failures ([`a426524`](https://github.com/doanythingK/FaceShield_/commit/a426524eeefa65c270d59b45cdbb3258fcc807b3)).
- **Verification:** Deferred; no retry or invalid-path restart executed.

### Toolbar, programmatic timeline and playback save barriers

- **Why:** A dirty face bitmap can be written by `FramePreviewViewModel.PersistCurrentMask()` into the legacy global manual layer unless the face-owned edit is saved first.
- **What:** View Save guard commits before toolbar Save and archives Undo on pointer entry ([`0fc996f`](https://github.com/doanythingK/FaceShield_/commit/0fc996f65257b7e4cb14286654b2dfd162064c35)). `WorkspaceSessionPlaybackCoordinator` commits/archives before UI/programmatic FrameList changes and playback, blocks navigation on failed target save, attempts to restore the prior frame, and does not clear the editor on rejected playback ([`88521b3`](https://github.com/doanythingK/FaceShield_/commit/88521b335673c474b7ff138948eec08963d2d940), [`78c0b77`](https://github.com/doanythingK/FaceShield_/commit/78c0b774237170eab9e1939b2f1ecb03319ce69d)). `ManualTargetUi.cs` exposes the actual editor frame and removes an outdated export blocker ([`9d56796`](https://github.com/doanythingK/FaceShield_/commit/9d56796592cd6058f711902eb9e4cb99af8757d9)).
- **Verification:** Deferred. **Remaining:** `PersistCurrentMask()` itself still has the global writer; direct preview calls, disposal and asynchronous startup are not all covered.

### Save/Auto failure handling and editor recovery

- **Why:** Failed target writes must block legacy-only export; legacy Auto refresh rebuilds the editor and clears the selected face's Undo.
- **What:** `TryCommitPendingManualTargetEdit()` reports failures while retaining dirty pixels ([`25bcd68`](https://github.com/doanythingK/FaceShield_/commit/25bcd681e9783f05ae262066cc37d0a327cd4307)). The view blocks Save, picker, new-face, pointer and key navigation on failure and retains its guard while the workspace lives ([`c09564a`](https://github.com/doanythingK/FaceShield_/commit/c09564acbad634a7292c31071c3ce80ddad63f05)). Target Auto lifecycle restores its editor and Undo after ordinary Auto completion ([`3aa2bde`](https://github.com/doanythingK/FaceShield_/commit/3aa2bde3e32c56313686d75e0799947bad60e695)). `ToolPanelViewModel.SetAuto` also runs the save guard ([`79119e9`](https://github.com/doanythingK/FaceShield_/commit/79119e9d055fd01da985c25b07a116454068842f)).
- **Verification:** Deferred; no failure injection or GUI Auto run. **Remaining:** Programmatic Save/Export outside those commands may bypass them; direct disposal remains uncovered.

### Face-specific tracking: disk-first result publication

- **Why:** Earlier `SetTrackSegment()` mutated live state before `Save()`, so a disk error could leave preview with an unpersisted track while export loads the previous document.
- **What:** Initially prevented a cancellation check between live mutation and save ([`3925d48`](https://github.com/doanythingK/FaceShield_/commit/3925d483333cb22cc77e42350eecfc82bc7720f4)). `ManualOverlayTargetTrackingService.TrackForward` now snapshots all faces, checks source fingerprint/interval, stages the longer retained or new segment, saves through `ManualOverlayWorkspaceStore.SaveForVideo`, and only then updates the live workspace ([`8b61f25`](https://github.com/doanythingK/FaceShield_/commit/8b61f255ceed0bc96262a64fae1a3297bf50700a)). `TrackSelectedManualTarget` no longer treats a late cancellation after the service returns its committed result as an uncommitted cancellation ([`0ea5b5d`](https://github.com/doanythingK/FaceShield_/commit/0ea5b5d878b4363039c580f3b9b4302c3aa60d92)).
- **Verification:** Deferred; no tracking, cancellation race, failed-write simulation, compiler or CI run.
- **Remaining:** This is **not** a cross-process transaction. Concurrent external writers or corrections between snapshot/save/live publication can still diverge; a no-sample retry with an older valid segment can still produce misleading status.

### Face-specific correction: disk-first write, selection and Undo

- **Why:** A target correction previously changed a live keyframe/track boundary before saving, potentially invalidating a verified track in memory after disk failure. Programmatic face selection also bypassed view-only Undo ownership.
- **What:** New `ManualOverlayTargetEditCommitter.cs` clones a full workspace snapshot, applies only that face's correction and preceding-track truncation to a candidate, validates and saves the candidate atomically, and then publishes the live correction ([`7564a93`](https://github.com/doanythingK/FaceShield_/commit/7564a93aa6570e8a5c8d0c4a45c60da8633b89aa)). `FramePreviewViewModel.ManualTargets.cs` uses it in brush-release, Undo and navigation, moves Undo archive/restore into the face selection setter, saves selected ID, and reports brush/Undo save failures while retaining dirty pixels ([`1207366`](https://github.com/doanythingK/FaceShield_/commit/120736692f0a0e2f7873521024ba12e868002c2e)). All-zero alpha remains an explicit absence boundary for the same face.
- **Verification:** Deferred; no build, GUI, disk-full simulation or two-face correction test.
- **Remaining:** No external-writer lock between candidate snapshot, file replacement and live publication; Undo archives remain session-only, and programmatic frame/disposal paths are not fully owned by the view-model.

### New-face creation and selection restore save the active state

- **Why:** Calling `CreateTarget()` on the live workspace before its `Save()` left an unsaved empty target after a failed write. Selection restoration could discard the outgoing target's Undo; restoring Undo with no selected face could clear legacy Undo.
- **What:** `CreateManualTarget` now opens a detached copy of the previously committed target file, creates and saves the new face there, and adopts that workspace only after successful save. The post-commit tracking status no longer throws a late cancellation ([`0ea5b5d`](https://github.com/doanythingK/FaceShield_/commit/0ea5b5d878b4363039c580f3b9b4302c3aa60d92)). `ManualTargetUndo.cs` leaves legacy Undo untouched without an active face/frame ([`4768d2b`](https://github.com/doanythingK/FaceShield_/commit/4768d2b83675a00967f742b768065173430412c5)). `ManualTargetLifecycle.cs` archives previous Undo and restores the saved face's archive around optional last-ID restoration ([`7088d6d`](https://github.com/doanythingK/FaceShield_/commit/7088d6d0b82dd90bb1ec7ba4b83423609466af2b)).
- **Source correction:** The first creation update accidentally changed tightly packed alpha indexing from `y * width + x` to `y * rowBytes + x` in `ExtractAlpha`. It was immediately reverted in [`bf2b591`](https://github.com/doanythingK/FaceShield_/commit/bf2b5911c3fb0e2fbefd0f5d8359945bacc7b978); the latter commit's diff confirms the index restoration. Neither revision has been compiled or exercised in GUI.
- **Verification:** Deferred by user; no build, test, live UI restart or simulated disk failure.
- **Remaining:** Detached creation reloads on-disk state, so independent concurrent writers must be excluded. An exception from `staged.Save()` still propagates from the synchronous new-face command and needs friendly UI handling; live target state is not swapped on that failure.
