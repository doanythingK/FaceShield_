# Manual overlay and tracking — implementation status

Branch: `refactor/manual-overlay-workflow`. This document distinguishes the existing application path from the separate, not-yet-integrated multi-target implementation. **The 2026-09-21 changes have not been built or tested at the user's request.**

## Intended workflow

Auto masks and manually selected masks must remain independently owned. A manually confirmed mask must apply on its exact frame without detector or feature-point requirements. Each manual target ultimately needs a stable ID, its own correction keyframes, validated tracking intervals and failure boundaries. Preview and export must use current-frame Auto plus only validated manual coverage. Missing manual samples must not become a stationary held mask or a falsely successful unblurred export.

## Existing application path — implemented before 2026-09-21

- `FrameMaskProvider` retains Auto face rectangles and stored manual bitmap layers on the same frame, including workspace snapshots. Auto updates do not remove a stored manual mask; the final mask unions their alpha.
- `ManualMaskEditorLayer` creates the editor's **manual-only** bitmap: an exact stored manual correction, a validated inherited manual raster, or an empty manual raster if neither exists. Auto pixels are never made writable manual pixels. Its `ComposeWithAutomatic` remains a disposable, non-cached compositor for other callers and tests.
- `FramePreviewViewModel` edits the manual-only bitmap when manual keyframes are enabled. It saves using `SetIndependentManualMask`, which does **not** strip overlapping manually painted alpha. `FramePreviewViewModel.ManualKeyframes` compares Undo and inherited editing against manual-only baselines. The pre-existing composite `SetMask` behavior remains for non-manual-keyframe callers; this is not a blanket migration of every legacy editor.
- **Manual preview cache:** the actual view-model uses `ManualPreviewCompositeCache`, not a new disposable full-frame Auto bitmap on each brush refresh. It caches the current frame's Auto raster and preview-only Auto/manual alpha union, updates only the dirty rectangle for an in-place brush edit, and forces a full redraw when the frame, Auto face collection, manual bitmap reference or session changes. Cached masks are released on frame/session replacement and disposal. Neither the editable manual bitmap nor export mask semantics are changed. This targets repetitive brush-preview work; it does **not** eliminate exact-frame seek/indexing or tracking decode time, and no real-video speedup percentage has been measured.
- `ManualTrackingSourceSelection` restarts from an exact stored manual correction or a validated, independently rasterized manual track result. Once manual keyframes exist, unrelated Auto-only detections are not used as continuation sources. If there is no verified manual source, continuation fails rather than selecting another Auto face.
- `ManualMaskTrackingService` performs forward/backward feature validation, similarity estimation or guarded sparse translation, scene-cut detection, and stops on missing evidence or decoder failure. It refreshes spatially distributed features inside the **current transformed manual mask** after a validated frame, avoiding an always-shrinking feature set. This is not a detector and cannot infer reliable motion from genuinely featureless frames.
- `ManualMaskTrackStore` v3 persists continuous per-component samples and rejects missing middle/tail samples, invalid transforms and duplicate source keyframes. Strict export loading rejects corrupt state. Failed continuation only retains verified samples; missing required samples are not silently held in place.
- The existing manual tracking timeline uses stored manual bitmap keyframes as correction boundaries when manual masks exist; Auto-only legacy sessions retain their previous source path. It combines verified tracked manual alpha with same-frame Auto in preview and export.
- **Safe retry:** a shorter retry from an unchanged source does not replace a longer, still-valid tracked segment. An equally long failed retry does not downgrade a successful interval; a successful equally long retry can update motion samples. Retention applies in the same global-keyframe timeline, not across independently identified manual targets.

## Independent multi-target implementation — still not wired into application

- `ManualOverlayTarget` has a stable nonempty GUID and same-target-only correction boundaries. `ManualOverlayMaskComposer` unions same-frame Auto and multiple verified manual alpha masks without filling missing frames.
- `ManualOverlayStateStore` now writes **version 2**: target ID, explicit compressed alpha keyframes **and per-target validated tracking components/samples/failure boundaries in the same atomically replaced state document**. It reads version 1 explicit-only files as empty-track targets. It rejects unknown track sources, duplicate source frames within one target, changed source fingerprints, missing middle/tail samples, invalid geometry and tracks crossing that target's next explicit correction. Other targets can independently use the same source frame. Corrupt or source-mismatched state fails rather than silently dropping manual coverage. It does not import the legacy global mask/track store.
- `ManualOverlayTargetWorkspace` provides target creation/selection, target-specific keyframe editing and removal, target-specific motion segment submission and retry protection, snapshot/save/load, and exact/validated-track frame resolution. A correction to A trims only A's preceding verified interval and removes A's old same-source track; B's keyframes and tracks are untouched. Removing a correction does not automatically extend an earlier unverified track. Fingerprints cover the individual target's alpha and dimensions, not the global Auto/manual union.
- `ManualOverlayTargetTrackingService.TrackForward` is a target-aware adapter around the existing `ManualMaskTrackingService`: it requires the chosen target's explicit source mask, uses only that target's next correction as the manual boundary, sets its alpha/dimensions fingerprint on returned samples, and saves a validated target segment through `ManualOverlayTargetWorkspace`. This adapter does **not** replace or connect the current GUI `FramePreviewViewModel.ManualTracking` command; actual integration remains necessary.
- The workspace's `TryComposeFrame` shares one target-owned resolver for future preview/export consumers: current-frame Auto plus exact or fully sampled masks from **all** targets, without a stationary fallback. Neither preview nor export currently invokes this resolver.
- `ManualOverlayWorkspaceStore` still places state at a video-path-derived independent location and checks video length and modification time. This is inexpensive metadata evidence, not a cryptographic content fingerprint. The actual application workspace/editor/export does not yet call this adapter or `ManualOverlayTargetWorkspace`.

## Remaining work and verification limits

1. **Actual application integration:** the application still stores one manual bitmap per frame and uses global manual correction boundaries. Connect target creation/selection to the real editor, Undo and brush ownership; wire the GUI tracking command to `ManualOverlayTargetTrackingService` with the selected target, then replace the legacy manual resolver in both preview and export. Do not expose an incomplete multi-target UI while preview/export would silently omit other targets.
2. **Persistence lifecycle and compatibility:** call the target workspace at real workspace open/save/close and recover target selection appropriately. Legacy global masks/tracks must be migrated only where identity is unambiguous; do not guess which face owns a bitmap or silently reinterpret old tracks. Ensure export fails closed for missing or corrupt required multi-target state.
3. **Unverified new code:** 2026-09-21 code has not been compiled or exercised; source-level design and data constraints are not evidence of correctness. Build, regression tests, real GUI and video checks are postponed at user request.
4. **Runtime/performance:** the preview cache reduces repetitive Auto rasterization and full-frame composition during brush edits, but actual Windows/macOS GUI responsiveness, high-resolution memory use, cold uncached-frame seek and long-video tracking latency remain unmeasured or unresolved. No speedup percentage is claimed.
5. **Visual accuracy and shipping parity:** test real moving faces, small or blurred targets, occlusion, rotation, scene cuts and near-edge cases, as well as GUI operation, decoded preview versus encoded output pixels, startup latency and packaged macOS FFmpeg dependencies. Synthetic fixtures do not establish real-face tracking accuracy or a missed-blur rate.

## Change log — 2026-09-20: preserve verified tracking on retry

- **Why:** `ManualMaskKeyframeTimeline.SetTrackSegment` unconditionally replaced a segment with the same source frame. A shorter or early-failing retry could silently erase already verified later frames in preview, export and persisted tracking JSON.
- **What:** Preserve a longer, still-current track when the new candidate has the same source fingerprint but a shorter interval; preserve a successful interval over an equally long failed retry. Different-source or equally long successful retries may replace the prior track. Surface retention in the tracking status. Production implementation: [`554081b`](https://github.com/doanythingK/FaceShield_/commit/554081b7c95c279dee22b5d51f3ad4d447c8d615). This protects the existing single-global-keyframe workflow; it does not add per-target IDs.
- **Tests:** Headless application regression checks early failure, shorter interval, preview, export snapshot, persisted state, equally long failed retry and successful full-length retrack. [One-shot integration run](https://github.com/doanythingK/FaceShield_/actions/runs/35489538971) passed macOS app build and headless regressions; [Quality Gate #299](https://github.com/doanythingK/FaceShield_/actions/runs/35489593929) passed Windows and macOS jobs, including FFmpeg synthetic integration. Earlier run failures from this step: none.
- **Remaining:** No per-face target identity/selection or independent same-target correction boundaries, no real-face tracking accuracy benchmark, and no packaged GUI/encoded-output parity test.

## Change log — 2026-09-21: target-specific tracking adapter (unverified)
