# Manual overlay and tracking — implementation status

Working branch: `refactor/manual-overlay-workflow`. **All changes dated 2026-09-21 remain unbuilt and untested at the user's request.** A committed source connection is not evidence of successful GUI operation, accurate tracking, complete data preservation, or correct encoded output. No merge to `main` was requested.

## Required workflow and invariants

A manually marked missed face is tracked independently of Auto detections and other manual faces. Each face owns a stable GUID, editable alpha, correction keyframes, validated motion samples and failure boundaries. Correcting face A cannot remove face B's track. Missing motion samples must not reuse a stationary earlier mask. Preview/export combine current-frame Auto, retained legacy manual coverage and confirmed face-specific coverage. Invalid saved target data or unresolved tracking gaps must not silently export an unblurred face.

## Baseline verified before 2026-09-21 only

- `FrameMaskProvider` separates Auto rectangles and legacy manual pixels; `ManualMaskEditorLayer` preserves strokes overlapping Auto. `ManualPreviewCompositeCache` caches the older global Auto/manual preview.
- `ManualMaskTrackingService` verifies feature motion and stops on unreliable motion, scene cuts or decoding failure. Legacy `ManualMaskTrackStore` v3 requires contiguous samples and retains a longer valid same-source retry.

## Change log — 2026-09-21 (no new build, CI, GUI or export validation)

### Retained retry status and optional selection loading

- **Why:** A rejected shorter retry could display its attempted frame count instead of the longer retained track; corrupt optional selection metadata could abort workspace opening.
- **What:** Return the retained, fingerprint-matching segment and its frame count; refuse tracking an all-zero explicit source ([`33fd5ae`](https://github.com/doanythingK/FaceShield_/commit/33fd5aee00450053f7f1132abac942bca38eecf8)). Resolve optional selection file paths inside the error boundary and avoid cleanup errors masking the original write failure ([`a426524`](https://github.com/doanythingK/FaceShield_/commit/a426524eeefa65c270d59b45cdbb3258fcc807b3)).
- **Verification:** Deferred; neither retry nor invalid-path restart was run.

### Toolbar, programmatic timeline and playback save barriers

- **Why:** A dirty selected-target bitmap can be written by `FramePreviewViewModel.PersistCurrentMask()` into the legacy global manual layer if target-owned persistence has not happened first.
- **What:** `WorkspaceView.axaml.cs` attaches the synchronous `ToolPanel.ManualTargetExportGuard`, which commits target-owned pixels before the toolbar Save command, and preserves Undo on pointer input ([`0fc996f`](https://github.com/doanythingK/FaceShield_/commit/0fc996f65257b7e4cb14286654b2dfd162064c35)). `WorkspaceSessionPlaybackCoordinator` commits/archives before GUI and programmatic FrameList changes and playback, blocks navigation on save failure, attempts to restore the prior frame, and avoids clearing an editor on rejected playback ([`88521b3`](https://github.com/doanythingK/FaceShield_/commit/88521b335673c474b7ff138948eec08963d2d940), [`78c0b77`](https://github.com/doanythingK/FaceShield_/commit/78c0b774237170eab9e1939b2f1ecb03319ce69d)). `ManualTargetUi.cs` exposes the actual preview frame and removes a stale export blocker ([`9d56796`](https://github.com/doanythingK/FaceShield_/commit/9d56796592cd6058f711902eb9e4cb99af8757d9)).
- **Verification:** Deferred. **Remaining:** The `PersistCurrentMask()` method itself still has the legacy global writer; direct preview calls, disposal and asynchronous startup are not all protected by the coordinator.

### Save/Auto failure handling and editor recovery

- **Why:** Failed target writes must not allow a legacy-only export or throw from every pointer callback; legacy Auto refresh clears a selected face's editor/Undo.
- **What:** `TryCommitPendingManualTargetEdit()` reports save failures while keeping dirty pixels ([`25bcd68`](https://github.com/doanythingK/FaceShield_/commit/25bcd681e9783f05ae262066cc37d0a327cd4307)). The view blocks Save, picker, new-face, pointer and keyboard paths on failure, and keeps the guard installed while the workspace lives ([`c09564a`](https://github.com/doanythingK/FaceShield_/commit/c09564acbad634a7292c31071c3ce80ddad63f05)). The target Auto lifecycle restores its editor and Undo after ordinary Auto completion ([`3aa2bde`](https://github.com/doanythingK/FaceShield_/commit/3aa2bde3e32c56313686d75e0799947bad60e695)). `ToolPanelViewModel.SetAuto` also runs the save guard ([`79119e9`](https://github.com/doanythingK/FaceShield_/commit/79119e9d055fd01da985c25b07a116454068842f)).
- **Verification:** Deferred; no failure injection or GUI Auto run. **Remaining:** Programmatic Save/Export calls bypassing these commands can still exist; direct disposal is not fixed.

### Face-specific tracking: disk-first result publication

- **Why:** Earlier `SetTrackSegment()` mutated the live workspace before `Save()`. A disk exception could leave preview using an unpersisted track and export loading the previous file. A cancellation between the two calls caused a related mismatch.
- **What:** First stopped checking cancellation between live mutation and save ([`3925d48`](https://github.com/doanythingK/FaceShield_/commit/3925d483333cb22cc77e42350eecfc82bc7720f4)). Then `ManualOverlayTargetTrackingService.TrackForward` moved to a stronger disk-first sequence: snapshot all targets, verify the source fingerprint and interval, construct an independent candidate containing the longer retained or new segment, call `ManualOverlayWorkspaceStore.SaveForVideo`, and only then call the live workspace's `SetTrackSegment()`. A failing file write now occurs before this method changes the live track ([`8b61f25`](https://github.com/doanythingK/FaceShield_/commit/8b61f255ceed0bc96262a64fae1a3297bf50700a)).
- **Verification:** Deferred; no tracking, cancellation race, disk-full simulation, compiler or CI run.
- **Remaining:** Saving and publishing are not a cross-process transaction. A concurrent external writer or correction between snapshot/save/live publication could still cause divergent state. The GUI can report cancellation after a committed result if cancellation arrives after return but before UI status is set. No-sample retry status still needs reconciliation.

### Face-specific correction: disk-first write, direct-selection Undo

- **Why:** `CommitSelectedManualTargetEdit` previously changed the live target keyframe/track boundary *before* saving. A failed save could invalidate a verified track in memory even though the disk retained the old document. Direct programmatic target selection also bypassed the view's Undo ownership hooks.
- **What:** New `Services/Video/ManualOverlayTargetEditCommitter.cs` clones the live workspace snapshot, applies only that face's correction and preceding-track truncation to the candidate, validates and atomically saves the whole target document, then publishes the correction in the live workspace ([`7564a93`](https://github.com/doanythingK/FaceShield_/commit/7564a93aa6570e8a5c8d0c4a45c60da8633b89aa)). `FramePreviewViewModel.ManualTargets.cs` uses it in brush-release/Undo/navigation commits, archives/restores per-target Undo within the selection setter and face creation, persists the selected ID, and surfaces callback save errors without discarding dirty pixels ([`1207366`](https://github.com/doanythingK/FaceShield_/commit/120736692f0a0e2f7873521024ba12e868002c2e)). Explicit all-zero corrections remain same-target absence boundaries.
- **Verification:** Deferred; no build, GUI, disk write failure injection or A/B face correction test.
- **Remaining:** A new target is still created in the live workspace before `_manualTargets.Save()`, so a failed creation write can leave an unsaved empty target. Staged correction publication assumes no concurrent writer changes the workspace between snapshot, disk replacement and live mutation; external cross-process locking is absent. Per-target Undo remains session-only and its restoration on direct frame/disposal paths is incomplete.

## Remaining implementation and verification

1. **Central persistence and disposal:** Make `FramePreviewViewModel.PersistCurrentMask()` itself target-aware and protect direct frame replacement, session initialization/switch and view-model disposal against unsaved edits. Avoid allowing dirty selected-face pixels into the legacy/global mask writer.
2. **Tracking and creation edge cases:** Prevent concurrent writers from racing snapshot/save/publication, reconcile late-cancel and no-sample retry UI status, and make new-face creation transactional on file failure. Audit other export entry points outside `WorkspaceExportCoordinator` without assigning guessed face IDs to legacy global tracks.
3. **Preview and memory:** Per-target preview composes full frames; fingerprint calculations, long-video latency, seeking and memory have not been measured.
4. **Deferred validation:** When requested, compile and run same-face/different-face correction tests, failure-injection and Undo/navigation tests, real GUI multi-face editing, actual decoded preview versus encoded export pixel parity, and Windows/macOS build/package checks. **None of the 2026-09-21 changes has been verified by these means.**
