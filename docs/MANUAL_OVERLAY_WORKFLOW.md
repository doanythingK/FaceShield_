# Manual overlay and tracking — implementation status

Branch: `refactor/manual-overlay-workflow`. Updated 2026-09-22. **The face-specific changes are NOT built or tested at the user's request.** Source inspection and successful GitHub commits are not evidence of compilation, GUI behavior, tracking quality, crash recovery or encoded-video fidelity. This branch has not been merged into `main`.

## Required behavior and user journey

The goal is **not** to create a separate storage system for its own sake: the user must be able to identify a face missed by Auto, draw a mask for that particular face, track it across moving video, correct it without affecting other faces, and see every verified mask in preview and final video. Each manually identified missed face has a stable GUID and independent explicit-alpha corrections, validated motion samples and failure boundaries. A correction to A must not erase B. Never hold an earlier face mask over a missing tracking sample. Preview and export should combine current Auto, separate legacy/global manual pixels and verified target-specific coverage. Corrupt target state and unresolved nonempty face gaps should block rather than silently export unblurred faces. An all-zero explicit correction terminates **only its own face**; no legacy/global mask is assigned an inferred face ID.

**Concrete steps, missing features, and unexecuted acceptance scenarios:** [`MANUAL_FACE_WORKFLOW_ACCEPTANCE.md`](MANUAL_FACE_WORKFLOW_ACCEPTANCE.md). Storage collision work supports the workflow but does not establish correct moving-face tracking or final output.

## Persistence and lifecycle corrections — 2026-09-21

- **Root issue:** `FramePreviewViewModel.PersistCurrentMask()` previously wrote the selected face's alpha into the legacy/global `FrameMaskProvider`. It now routes a selected face through `CommitSelectedManualTargetEdit()` first. ### Competing edits and direct writer integration

- **Initial conflict protection:** `CommitIfUnchangedForVideo` compares target IDs, alpha keyframes, tracking samples and failure metadata with the disk document under a persistent sidecar lock file. Correction, tracking and detached new-face creation use expected-state comparison. [Compare-and-commit `9d5d88a`](https://github.com/doanythingK/FaceShield_/commit/9d5d88a0cf40d722850c948ab2eab8f23b8f7a9a), [correction `df8065f`](https://github.com/doanythingK/FaceShield_/commit/df8065f32dcc5624ed88ca724ee7acffb3fd5c05), [tracking `b843ea6`](https://github.com/doanythingK/FaceShield_/commit/b843ea68521718964397798f521c6c8e034e7de8), [creation `8a90b7c`](https://github.com/doanythingK/FaceShield_/commit/8a90b7c62b7bbcb5a46bb4bc303cb57922e4d63e).
- **Direct `ManualOverlayTargetWorkspace.Save()` no longer overwrites unconditionally:** A workspace stores its last loaded/confirmed persisted snapshot, compares it to disk when directly saving, and advances its baseline only after successful persistence. Disk-first correction/tracking committers now record their newly saved snapshot after live publication, so later direct saves do not falsely conflict with their own changes. [Workspace `575e2b2`](https://github.com/doanythingK/FaceShield_/commit/575e2b2941e642f3bb4de62fd7cde943f0cecf34), [correction baseline `641c133`](https://github.com/doanythingK/FaceShield_/commit/641c1337827503a1ec6ab6faf3d1514abf972f45), [tracking baseline `4e824f5`](https://github.com/doanythingK/FaceShield_/commit/4e824f59803e69d22b20d8daa88f58dac35ed31c).

Updating existing state through that API requires migrating the caller to `CommitIfUnchangedForVideo(expected,updated)`; an older caller relying on unconditional replacement will now receive a conflict. Optional `stateDirectory` remains supported for synthetic scripts. ## Tracking boundary, export and operation admission — 2026-09-22

- **Estimated frame counts cannot end target tracking:** The target tracking service passes `totalFrames: 0` to same-face `NextBoundaryExclusive`, regardless of caller-provided display estimate. The UI uses that same unbounded-or-next-correction boundary; an estimate is only a progress denominator, capped at 99% until completion. An unbounded tracker reaches the FFmpeg sequential decoder's checked EOF instead of stopping at an undersized `nb_frames` estimate. [Tracking boundary `d723f6b`](https://github.com/doanythingK/FaceShield_/commit/d723f6b9fb90b234b78ed758f24ca3818279c18c), [UI boundary and callback `2fca882`](https://github.com/doanythingK/FaceShield_/commit/2fca88238e907eb41e59e5ea61544a66612e68fb). The existing legacy manual-tracking path already uses `GetNextExplicitKeyframe(..., totalFrames: 0)`; its estimate is only a progress hint.
- **EOF result is separate from a correction boundary:** The tracking service optionally reports the decoded frame count only when an *unbounded* attempt completes at decoder EOF without a tracking failure. The preview passes this result to the owner, which updates `FrameList.UpdateActualTotalFrames` on the UI thread. Neither a finite next-keyframe boundary nor a failed/cancelled attempt promotes an estimate. [EOF callback `85531c5`](https://github.com/doanythingK/FaceShield_/commit/85531c5e8073c2598118a776897de8f5a2134223), [preview owner contract `0756430`](https://github.com/doanythingK/FaceShield_/commit/07564304c714db4caf60ddf03105a27807d30302), [workspace timeline `1e9b144`](https://github.com/doanythingK/FaceShield_/commit/1e9b14417b57d1dfe5e21ee1ca5dfb2a63b0a27f).
- **Export sample lookup and strict single composition:** The workspace uses `SortedList` keyframe binary floor lookup, cached source fingerprints and O(1) ordinal `sampleIndex = frameIndex - sourceFrame - 1` with an explicit frame-index check on every component. The export wrapper no longer searches/sorts per frame or transforms each face once for preflight and again for composition. `TryComposeFrame(..., requireCompleteTargets: true)` transforms each target once and immediately unions alpha into the output BGRA buffer; a nonempty face with a missing sample still throws, while an explicitly absent face does not require a sample. [Indexed resolver `5eed014`](https://github.com/doanythingK/FaceShield_/commit/5eed01499017a0c20dd7a40327113142b1a6f8da), [export entry point `99fd3ab`](https://github.com/doanythingK/FaceShield_/commit/99fd3abcbb8baa6b9ad43f29e4a3f40ae2f00db3), [cached absence `815310b`](https://github.com/doanythingK/FaceShield_/commit/815310be7d57d97617225e246429090f01f4553a).
- **Auto and manual track share atomic exclusive admission:** `WorkspaceOperationLifetime.TryBeginExclusiveProcessing` admits only one processing run under its sync lock, separately from the ordinary disposal/lifetime lease. The Auto coordinator and selected-face tracking ownership both acquire this gate. Auto-owned export takes only the ordinary lifetime lease, avoiding recursive acquisition of the exclusive gate. Public `RunAutoAsync` and single-frame Auto also check editor/session/tracking flags before entering. [Exclusive gate `7adf968`](https://github.com/doanythingK/FaceShield_/commit/7adf968077d1c19b2309e3c6d72a9421a37fdd96), [manual owner `f96d717`](https://github.com/doanythingK/FaceShield_/commit/f96d717e4a1ef9b5c97354de9615ef6745cd73bf), [Auto admission `aef6fae`](https://github.com/doanythingK/FaceShield_/commit/aef6fae72817d198cfa6edc8c4e8e800624b3abe).

## Known limitations / still unfinished

1. **The core purpose is not proven:** An actual missed face's moving mask must be checked end-to-end from manual draw through tracking, separate-face correction, preview and encoded video. No such execution has been performed. Face list ordinal labels can change after reopening despite stable GUIDs; friendly names/thumbnails are not persisted.
2. **Uncooperative writers and conflict recovery:** A separate process bypassing `CommitIfUnchangedForVideo`/the sidecar lock (or calling the lower-level `ManualOverlayStateStore.Save` directly) can still race. Conflicts fail closed and currently require reload/manual reconciliation; there is no automatic three-way merge. Source evidence is video length and modification time, not a content hash.
3. **Shutdown and navigation edge cases:** Forced process/OS termination or permanent disk write failure cannot guarantee recovery of memory-only edited pixels. Ordinary close can be cancelled but may not cover every OS shutdown path. A direct programmatic timeline setter can leave selection visually inconsistent when an asynchronous preview save rejects; confirm exception/cancellation and ownership transitions in real GUI. **Direct `FramePreviewViewModel.Dispose()` still needs unconditional tracking/load/playback task drain registered on `VideoSession` independently of the optional keyframe PropertyChanged handler.**
4. **Other export entry points:** `WorkspaceExportCoordinator` wraps target state; unrelated direct `VideoExportService`/other export consumers may bypass its pre-save guard or target mask adapter. Audit all production call sites before claiming universal face-specific export protection. Independent export entry and single-frame Auto are not yet uniformly protected by an exclusive processing admission; the new gate specifically prevents concurrent Auto/manual-tracking starts.
5. **Runtime, accuracy and memory:** The O(N²) sequential sample search and double target transform are removed in source, but a full-frame target alpha is still allocated for each transform; legacy BGRA, merged BGRA and output `WriteableBitmap` are still allocated per export frame. `IFrameMaskProvider.GetFinalMask(int)` does not accept a cancellation token, so new cancellation checks within composition are not yet wired from the export caller. Benchmark and scratch-buffer/`TryComposeFrameInto` design remain open. Seek/decoder failures, zero-sample retrack exceptions, large/VFR video and packaged FFmpeg behavior remain unmeasured. Actual decoded preview vs encoded video parity has not been established.
6. **Verification deliberately deferred:** Compilation, regression scripts, injected disk failure, concurrent writer test, real multi-face GUI, preview/encoded-output comparison and Windows/macOS builds/packaging were **not executed for the new face-specific implementation**. [Quality Gate #299](https://github.com/doanythingK/FaceShield_/actions/runs/35489593929) pertains only to old [`554081b`](https://github.com/doanythingK/FaceShield_/commit/554081b7c95c279dee22b5d51f3ad4d447c8d615), not these changes. No performance gain has been measured.

Subsequent changes must be committed on this branch and recorded here with reason, commit link, actual verification or explicit deferral, and remaining limitations. Do not equate source intent with tested behavior.
