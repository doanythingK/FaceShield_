# 수동 마스크 피라미드 메모리 개선 및 검증

## 변경 범위

- `ManualImagePyramid`는 해상도별 `float[]`를 생성 시 한 번 할당하고 `Reload`에서 같은 배열을 다시 채웁니다.
- `ManualMaskTrackingService.TrackForward`는 이전·현재 피라미드 두 개만 보유합니다. 다음 프레임의 장면 전환 검사 후 비활성 피라미드에 값을 채우고, 모든 마스크 영역을 검증하여 해당 프레임 결과를 확정한 뒤에만 두 피라미드를 교환합니다.
- 영상 크기가 고정된 하나의 추적 실행 안에서만 버퍼를 재사용합니다. 공유 전역 풀과 native 디코더 수명 정책은 바꾸지 않았습니다.
- 자동 블러, Preview/Export 렌더링, 마스크/키프레임 저장 형식은 변경하지 않았습니다.

## 배열 메모리 산식

480×270을 4단계로 축소하면 `480×270 + 240×135 + 120×67 + 60×33 = 172,020`개의 `float`가 필요합니다. `float` 4바이트 기준 **피라미드 1개당 688,080바이트(약 0.688 MB, 약 0.656 MiB)**, 2개는 **1,376,160바이트(약 1.376 MB, 약 1.312 MiB)**입니다. 이 값은 `float[]` 요소 데이터만 계산한 값이며 배열 헤더, 특징점, BGRA 버퍼 및 디코더 메모리는 제외합니다. 예전에는 후속 프레임마다 이 크기의 새 `float[]`를 만들었지만, 현재는 한 추적 실행의 피라미드 초기화 시 두 벌을 만들고 다시 사용합니다. **메모리 누수 수정이 아니라 반복 할당 완화**입니다.

## 재현 가능한 피라미드 단위 검사

```bash
bash scripts/verify-manual-pyramid.sh
```

스크립트는 임시 .NET 8 프로젝트에서 현재 `ManualMaskVision.cs`를 컴파일하여 패딩 stride·홀수 해상도에서 생성 직후 피라미드와 재사용 피라미드의 모든 픽셀 결과가 일치하는지 확인합니다. 또한 버퍼 참조 유지, 이전 프레임 불변성, 취소 후 재사용, 동일 프레임의 광학 흐름 결과 일치 여부를 확인하고, 480×270 영상 프레임 40회 처리에 대한 **해당 스레드의 피라미드 생성과 `Reload` 관리형 할당 바이트**를 각각 출력합니다. 새로 생성하는 경로의 할당량과 재사용 경로의 할당량을 **동일 리비전에서 비교**하므로 이전 릴리스 전체 영상의 실행 시간 비교 자료가 아닙니다. CI에서는 macOS 빌드 뒤 이 검사를 실행합니다.

## FFmpeg 디코딩을 포함한 합성 영상 통합 검사

```bash
bash scripts/verify-manual-tracking-integration.sh
```

macOS 환경과 Homebrew `ffmpeg@8`, .NET 8이 필요합니다. 이 스크립트는 320×180, 30fps, 총 780프레임의 합성 FFV1 영상을 생성합니다. 처음 750프레임은 동일한 텍스처이고 750번 프레임부터 검정 화면으로 전환합니다(프레임 번호는 0부터 시작). 실제 `FfFrameExtractor`로 749·750번 프레임 번호를 확인하고, Avalonia Headless `WriteableBitmap`을 마스크로 만들어 프로덕션 `ManualMaskTrackingService.TrackForward`를 550번 프레임부터 호출합니다. 취소 동작, 551~749번의 연속 결과 199개, 750번에서 장면 전환 중단, 유한한 추적 변환을 검사합니다. 임시 프로젝트는 실제 `FaceShield.csproj`를 참조하며 앱에 테스트 진입점을 추가하지 않습니다.

[Hardening Quality Gate #207](https://github.com/doanythingK/FaceShield_/actions/runs/35193850558)의 macOS 작업에서 위 합성 통합 검사는 통과했습니다. 한 차례 실행한 추적 구간 측정치는 `synthetic_tracking_elapsed_ms=1043`, `managed_allocated_bytes=6462720`, `gen0_collections=0`입니다. macOS의 `PeakWorkingSet64` 반환값이 0이므로 해당 값으로 최고 메모리를 판단하지 않습니다. **실제 영상의 성능·정확도, 장시간 안정성 또는 이전 버전 대비 개선율을 나타내는 결과가 아닙니다.**

### macOS 네이티브 라이브러리 검증 범위 주의

[Quality Gate #206](https://github.com/doanythingK/FaceShield_/actions/runs/35193638806)에서 저장소의 기존 `FFmpeg/osx-arm64` 라이브러리를 임시 실행 폴더로 복사했을 때, `libavcodec.62.11.100.dylib`가 `/opt/homebrew/Cellar/ffmpeg/8.0.1/lib/libswresample.6.dylib`라는 절대 설치 경로를 참조해 깨끗한 CI 머신에서 로딩에 실패했습니다. 이는 **번들 라이브러리의 해당 CI 실행 경로에서 재현된 문제**이지, 배포된 `.app`에서도 반드시 실패한다는 증거는 아닙니다. 배포 시 `scripts/collect-macos-dylibs.sh`가 별도로 라이브러리 수집과 install name 변환을 수행합니다.

#207 합성 추적 검사는 생산용 소스 코드는 그대로 둔 채 임시 테스트 실행 폴더에서 Homebrew의 호환 `ffmpeg@8` 라이브러리를 사용해 통과했습니다. **저장소의 FFmpeg 번들 또는 macOS 배포 패키지의 독립 실행 가능성까지 통과했다고 해석해서는 안 됩니다.** 원래 번들 의존성 및 실제 배포 `.app` 검증은 별도 작업입니다.

## 남은 실사용 검증

- 실제 영상에서 회전·이동·가림을 포함한 추적 정확도, 처리 시간, 전체 애플리케이션 GC 횟수/일시정지, 디코더 메모리 및 동시 작업 자원 사용량 측정.
- 사용 중인 원본 영상의 550프레임 추적 시작과 750프레임 장면 전환 감지/중단 프레임 확인. 원본 영상이 없으므로 이 항목은 **미검증**입니다. 이번 750번 장면 전환 통과는 **합성 영상에 한정**됩니다.
- 수동 블러 GUI의 타임라인 클릭/연속 클릭/프레임 이동 버튼/캐시 표시 및 Preview/Export 일치 확인. GUI 실행 검증은 **미완료**입니다.
- macOS 배포 `.app`의 네이티브 의존성 경로와 깨끗한 머신에서의 FFmpeg 로딩 검증.
- 타임라인 전용 `FfFrameExtractor`는 PTS 탐색을 썸네일 작업과 분리하기 위한 의도된 구조로 유지했습니다. 통합 여부는 실제 초기화 시간·상주 메모리·경합을 측정한 뒤 판단합니다.
